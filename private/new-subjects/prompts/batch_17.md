## サイトの方針（必ず守る）

1. **答えがはっきり決まる問題にする**。基本は求値問題（〜を求めよ）。証明問題は，示す結論が式として決まっているもの（「〜となることを示せ」）や，試験に出る定番の証明（公式・定理の導出など）に限る。比べよ・考察せよ・述べよのように答え方が人によって変わる問いは作らない。目安は，試験に出しても採点できるかどうか。
2. **手を動かして式を扱えるようになること**が目的。小問は2-3個を基本とし，4個にするのはどうしても必要な場合だけにする。前の小問の結果を次で使う流れにする。小問どうしは同じ話題でつなげる（関係の薄い小問を1問に詰めない）。1つの小問で問うのは原則1つ。「Aを求め，Bを求め，この場合について計算せよ」のように1つの小問に問いを重ねない。問うことが多くなる場合は，周辺的な問いを削るか，問題を2つに分ける。
3. **問題文で答えや公式を先に与えない**。解くのに必要な定義・記号・条件（正負，範囲，近似の前提）だけを書く。誘導が必要なら「〜を考えよ」「〜を用いて」とヒントにとどめる。
4. **難易度**：基本＝学部の定期試験レベル，標準＝院試の基本問題レベル，発展＝院試でたまに見る発展的な内容。院試を超える内容は入れない。
5. **具体的な数値計算は控えめにする**。数値を代入するだけの小問は，試験によく出る定番（フェルミエネルギーの見積もりなど）に限り，1分野に数問程度にする。基本は文字式で答える問題にする。
6. **問題文は短くする**。必要な定義・記号・条件だけを書き，背景の説明や長い前置きは入れない。問題文で与える式が長いときは別行の数式にする。
7. **すべての答えを自分で検算する**（式変形・積分・次元・特別な場合の極限）。誤りがある問題は有料の PDF にもなるので，正確さを最優先にする。

1問を1ファイルとし，各ファイルの直前に次の区切り行を置く（区切り行はそのまま書く。コードブロックで囲まない）。

```

```

ファイルの中身は次の形。

```

### (1)
解説（です・ます調）

$$
\finalanswer{答えの式}
$$

### (2)

```

- `tags` は `基本` `標準` `発展` のいずれか1つ。
- 小問は `(1)` で始まる段落にし，段落の間は空行。箇条書きにしない。
- 区切りの `---` と `## 解答・解説` の見出しはこの綴りのまま。解説は小問ごとに `### (1)` の見出し。
- 句読点は全角の「，」と「。」。

## 数式の書き方

- インライン数式は `$...$`。**`$` の内側の先頭と末尾に空白を入れない**（`$ x $` は表示されない）。
- 別行の数式は `$$` を前後の行に単独で置く。複数行は `\begin{aligned} ... \end{aligned}` を使い，改行は `\\`（バックスラッシュ2つ）。`\\\\` にしない。
- 文中に大きな分数（`\dfrac` で縦に大きくなるもの）や長い式を置かない。文中に置いてよいのは `$2\pi/a$` のようなスラッシュ形の短い式だけで，それ以外は別行の数式に出す。別行の式の分数は `\frac`。
- 数式の中（`$...$` や `\text{}` の中）に日本語を書かない。場合分けの条件は本文に書き，場合ごとに別の式にする（`\text{電子の場合}` や `(n\ \text{は整数})` のように数式に日本語を入れない）。ベクトルは `\boldsymbol{a}`，単位ベクトルは `\boldsymbol{e}_x`。
- 使う記号はすべて問題文か解説で定義する。分野の中で記号をそろえる。
- **最終的な答え**は `\finalanswer{...}` で囲む。サイトでは黄色の下地になる。
  - 答えの関係式全体を囲む（`\finalanswer{v=\sqrt{2gh}}`）。右辺だけ・数値だけを囲まない。
  - 導出の最後の行が答えなら，その行の答えの部分を囲む（`&= \finalanswer{...}`）。
  - 1つの小問で答えが複数あれば，それぞれを囲む。
  - 証明問題では，示すべき式が得られた行を囲む。
  - **問題文の中では使わない**。太字（`**`）も問題文では使わない。

## 解説の書き方

- 各ステップに「何をするか・なぜそうするか」を1文で書いてから式を置く。式だけを並べない。
- 計算の途中経過を文中の `$...$` でつながない（「〜を代入すると $A=B$ だから $C=D$ となり」のような書き方をしない。スマホでは読みにくい）。2段以上の変形や積分は別行の数式に出し，`aligned` で等号をそろえて1行に1段ずつ書く。文中の `$...$` は記号の定義や短い式1つにとどめる。
- 別行の数式も1行が長くならないようにする。`A=B=C` の連鎖や，`\qquad` で横に並べた2つの式は，`aligned` で縦に並べる。
- 最後の式のあとに「となります。」などの短い締めを必ず置く（式で終わらせない）。
- 文と式をつなぎで結ぶ。答えの別行数式の前には「したがって，」「よって，」「代入すると，」などのつなぎを置き，前の文から突然式に移らない。文が並ぶだけで論理のつながりが見えない解説にしない。
- 積分や和の計算を「積分すると，」の一言で済ませない。置換や部分積分などの途中経過を `aligned` で示す。「〜と比べると」「〜に代入すると」と書くときは，何と何を比べるのか，何に代入するのかを式で明示する。
- 最後に，結果の意味（極限での振る舞い，向き，大小，物理的な解釈）を1文添えてよい。
- 次の言い方は使わない：
  - 手順の実況（「両辺を2で割り算します」「等式を組み立てます」「整理をおこないます」）→「両辺を2で割ると，」のように短く。
  - 内容を繰り返すだけの締め（「これにより〜が示されました」「以上より〜が導かれます」）。
  - 「よく合います」「〜に戻ります」「〜が支配します」のような言い回し。極限で既知の結果と一致するときは「〜と一致します」と書く。
  - 丸括弧（ ）で補足を差し込む書き方。補足は独立した文にするか，文の中に組み込む。ただし，数式の条件（$x>0$ など）や（図）は括弧でよい。
  - かぎ括弧「 」を使った強調。用語は太字にもかぎ括弧にもせず，そのまま書く。
- 解説の長さは1問あたり本文400〜700字程度（数式を除く）。

## 図について（図は別の担当が描く）

図はあなたは描かない。図があると理解が大きく助かる場所に，次の形の**図の依頼**を HTML コメントで書く。図の担当がこれを読んで作図し，差し替える。

- 問題図（状況の見取り図）：問題文の最後の段落のあと，`(1)` の前に置く。問題文の中には「（図）」と書いておく。

```
<!-- FIGURE problem: 何を描くか（形・配置・ラベルにする記号・寸法の示し方）。答えにつながる情報（求める力の向き・結果のグラフなど）は描かない。 -->
```

- 解答図（グラフや説明の図）：解説の中，図を見せたい位置に置き，直前に図を導入する1文（「〜を図に示します。」）を書く。

```
<!-- FIGURE solution (2): 何を描くか（軸の名前，曲線の数と違い，目印にする点や値）。 -->
```

- グラフの図の依頼には，横軸と縦軸の量，原点 O を必ず書く。
- 図の依頼は1問につき0〜2個。必要のない問題には入れない。説明は図の担当が問題を読まずに描けるくらい具体的に。
